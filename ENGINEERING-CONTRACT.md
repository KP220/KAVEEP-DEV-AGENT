# Purpose

This document defines the engineering contract between KAVEEP-DEV-AGENT and the rest of the KAVEEP ecosystem.

The contract specifies what KAVEEP-DEV-AGENT guarantees, what it requires from other platforms, and what responsibilities remain outside its scope.

This contract establishes a stable interface between engineering and the broader KAVEEP platform.

---

# Responsibilities

KAVEEP-DEV-AGENT is responsible for:

- Engineering planning
- Repository understanding
- Requirements analysis
- Architecture engineering
- Specification engineering
- Governed implementation support
- Governed code improvement
- Documentation generation
- Testing support
- Validation
- Audit evidence
- KCP verification coordination
- Engineering reports
- Release preparation

---

# Responsibilities Outside Scope

KAVEEP-DEV-AGENT is NOT responsible for:

- Platform governance
- Business strategy
- Final policy decisions
- Human approval
- Runtime orchestration
- Production monitoring
- Knowledge consensus
- Organization management
- Acting as an unconstrained chatbot
- Acting as an ungoverned AI coding assistant
- Bypassing validation, audit, KCP verification, or approval

These responsibilities belong to other official KAVEEP platforms.

---

# Engineering Boundaries

KAVEEP-DEV-AGENT shall operate within the following engineering boundaries.

Governance Boundary

KAVEEP-DEV-AGENT may evaluate and apply approved engineering governance, but it shall not replace KAVEEP Constitution, KAVEEP Roadmap, KAVEEP-POLICY, or authorized human approval.

Architecture Boundary

KAVEEP-DEV-AGENT may propose or document architecture changes, but protected architecture changes require the approval path defined by the Engineering Constitution.

Implementation Boundary

KAVEEP-DEV-AGENT may support implementation only after sufficient engineering context, specifications, risk classification, and validation strategy exist.

Runtime Boundary

KAVEEP-DEV-AGENT defines engineering behavior and may prepare runtime work, but it does not own production runtime orchestration or production monitoring.

Knowledge Boundary

KAVEEP-DEV-AGENT may consume and produce engineering knowledge, but verified knowledge authority belongs to KCP-aligned knowledge governance.

LLM Boundary

KAVEEP-DEV-AGENT may use Cloud Brain and Local Brain providers through an LLM Adapter, but no model provider shall become the source of engineering authority.

Human Boundary

KAVEEP-DEV-AGENT may recommend, validate, report, and prepare work, but humans retain final authority for protected engineering actions.

Security Boundary

KAVEEP-DEV-AGENT shall operate inside approved sandbox, repository, path, credential, and tool boundaries.

Completion Boundary

KAVEEP-DEV-AGENT shall not consider engineering complete when code is written. Completion requires validation, audit evidence, KCP verification where applicable, documentation consistency, and required approval.

Engineering Plans are DEV-AGENT-owned proposal artifacts.

An Engineering Plan may support policy evaluation, sandbox preparation, and final reporting.

An Engineering Plan does not authorize implementation, external writes, Git writes, merge, release, deployment, or destructive action.

Engineering Requests are DEV-AGENT-owned interpreted-intent artifacts.

An Engineering Request may be produced by the Thai Command Interpreter and consumed by the future Planning Engine.

An Engineering Request does not authorize planning output, policy approval, implementation, external writes, Git writes, merge, release, deployment, or destructive action.

The Planning Engine is a DEV-AGENT-owned read-only runtime foundation.

It transforms validated Engineering Requests into Engineering Plans.

It does not inspect repositories, perform policy evaluation, approve protected actions, execute tools, create sandboxes, modify files, access Git, or call external providers.

Repository Intelligence Context is DEV-AGENT-owned task-oriented discovery evidence.

It may support planning through bounded observations, repository context summaries, and relevant file references.

It does not replace KAVEEP-RO repository assessment, architecture compliance review, repository health review, standards review, or post-change review.

It does not authorize implementation, file modification, external writes, Git writes, merge, release, deployment, or destructive action.

Engineering Context is a DEV-AGENT-owned deterministic selection of Repository Intelligence observations relevant to one Engineering Request.

It preserves request, repository intelligence, path, relevance, and evidence traceability while reducing unrelated repository context.

It does not inspect repositories, replace KAVEEP-RO, make policy or approval decisions, authorize planning execution, or authorize implementation.

Tool Requests and Tool Results are DEV-AGENT-owned read-only invocation contracts. They record proposed or actual registered read-only tool access; they do not replace POLICY, Approval Gateway, Secure Sandbox, or COMMAND-CENTER agent registry ownership.

# Engineering Guarantees

KAVEEP-DEV-AGENT guarantees:

- Engineering traceability
- Policy compliance
- Architecture consistency
- Specification alignment
- Explainable recommendations
- Structured engineering reports
- Validation evidence
- Audit readiness

---

# Non-Guarantees

KAVEEP-DEV-AGENT does not guarantee:

- Business success
- Market success
- Perfect software
- Zero defects
- Autonomous authority over governance
- Automatic production deployment

---

# Contract Stability

This contract is designed to remain stable across AI model changes, programming languages, runtime environments, and implementation technologies.

The contract defines engineering behavior rather than engineering implementation.
